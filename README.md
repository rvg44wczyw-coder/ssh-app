Native iOS mobile application (**SwiftUI + Rust Core via UniFFI**) for securely managing remote terminal sessions and autonomous AI coding agents (*Claude Code*, *Google Antigravity*, *OpenAI Codex*, *Grok*, *Ollama / local models*) on your MacBook / remote server over Tailscale.

## Key Technical Features

### 1. Zero Battery Drain
- **Instant Socket Teardown**: When minimized (`sceneDidEnterBackground`), the TCP socket is immediately closed.
- **0% Idle CPU & Radio Usage**: The iPhone does not maintain background polling sockets.
- **Persistent Agent Execution**: The host persists long-running agent tasks safely inside `tmux`.
- **Instant Re-Attach**: On foregrounding (`didBecomeActive`), the Rust core instantaneously reconnects and re-attaches to the tmux session.

### 2. Zero Network Attack Surface on Host
- **No listening ports, no daemon**: `ssh-app` opens **ZERO** listening TCP/HTTP ports on the host and runs no background service. Agent hooks talk to the app through a small file queue under `~/.ssh-app/run` (directories `0700`, files `0600`, owned by you) and the app reads and answers it over SSH.
- **Authenticated SSH**: All remote communication is routed through authenticated SSH channels (`russh` with Ed25519 keys) over Tailscale WireGuard, with host key verification.

### 3. Cryptographic Phone Approvals
- **Ed25519 signatures**: Approvals are signed on the phone with an Ed25519 key generated by the Rust core and stored in the iOS Keychain (`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, never synced). The signature is an OpenSSH `SSHSIG` over a domain-separated payload: `SSH_APP_APPROVAL_V1:{id}:{command_hash_sha256}:{nonce}:{timestamp}:{approved}`.
- **Verified on the host**: the hook checks the signature with `ssh-keygen -Y verify` against `~/.ssh-app/allowed_signers` and its **own copy** of the request, then answers the agent. No valid answer in time (or any error) means the hook has no opinion and the agent asks in the terminal as usual; it never approves on its own.
- **Replay protection**: a freshness window of 120 seconds and single-use CSPRNG nonces.

### 4. Zero-Knowledge Wake-up Pings ($0/month)
- **Cloudflare Worker APNs Gateway**: A stateless Cloudflare Worker ([`scripts/apns-worker/worker.ts`](scripts/apns-worker/worker.ts)) forwards empty wake-up notifications (`content-available: 1`).
- **Total Privacy**: The worker receives **ONLY** an opaque 64-character hex device token. **Zero command text, zero file paths, and zero code snippets ever touch third-party cloud servers.**
- **Cost**: Runs completely on the Cloudflare Workers Free Tier (100,000 requests/day included, $0/month).

### 5. Agent Hooks, Templates and Host Guard
- **33 hook templates** (phone approval variants, notifications, guards that block `rm -r`, force pushes, `sudo`, `curl | sh`, secrets and agent config, logging, auto-format and snapshot helpers), picked per agent profile and previewed before anything is written to the host.
- **Host guard** (`~/.ssh-app/guard.json`): deny / always-ask / allow rules enforced by the hook before anything reaches the phone, plus user-written context for sessions and prompts and a "keep going" message when the agent stops.
- **Permissions editor** for Claude Code (`allow` / `ask` / `deny` / default mode) with templates, suggestions and guarded apply; the hooks are checked for drift against the profile.
- Details: [`docs/features/11`](docs/features/11-agent-hooks-and-launch-profiles.md), [`13`](docs/features/13-host-approval-broker.md), [`14`](docs/features/14-agent-permissions-and-hook-settings.md), [`15`](docs/features/15-hooks-capability-analysis.md), [`19`](docs/features/19-hooks-templates-and-host-guard.md).

### 6. Developer Experience & UI
- **Sessions home screen**: every open session as a card with a live preview of its screen; tabs and a long-press jump menu (other sessions, servers and their sessions, new session plain / from a preset / with new settings).
- **Terminal rendering**: SwiftTerm with TrueColor, tmux mouse scroll and tap, 17 built-in color schemes plus your own, per agent or profile.
- **Approval banner**: agent, command with risk flags and the end of long commands, countdown on the host clock, Approve / Deny.
- **Quick commands bar** above the keyboard (`^C`, `y`/`n`, your own buttons such as `/clear` with an optional confirmation); Esc, Tab, Ctrl and arrows stay on the system bar.
- **Tools**: Git diff viewer, remote file browser, host monitor (CPU, memory, processes), in-app web preview over SSH port forwarding, snippets with fuzzy history search, AI command assistant and local chat through Ollama on the host, model usage line.
- **Privacy masking**: full-screen overlay when the app is backgrounded, so output does not appear in the App Switcher.

### 7. Payments (built, switched off)
A StoreKit 2 Pro subscription (weekly / monthly / yearly with trials) and lifetime purchase exist in the code but are disabled by default (no `PAYMENTS` build option); the app is free for now. See [`docs/features/18-payments.md`](docs/features/18-payments.md).

## Getting Started

### Prerequisites
- macOS Sonoma or later
- **Rust**: 1.85+ with Apple targets:
  ```bash
  rustup target add aarch64-apple-ios aarch64-apple-ios-sim aarch64-apple-darwin
  ```
- **Xcode**: 15.0+ or 16.0+
- **Tailscale**: Installed and configured on your Mac and iPhone

### 1. Build Rust Core & XCFramework (iOS)
Clone the repository and compile the multi-architecture framework:
```bash
git clone git@github.com:rvg44wczyw-coder/ssh-app.git
cd ssh-app
./scripts/build-xcframework.sh
```
This builds:
- `aarch64-apple-ios` (Physical iPhone / iPad)
- `aarch64-apple-ios-sim` (Apple Silicon iOS Simulator)
- `aarch64-apple-darwin` (macOS / SwiftUI Previews)
and writes `ssh_coreFFI.xcframework` into `packages/SshCoreBridge/Frameworks/`.

### 2. Build Rust Core & Android Native Libs (Android)
Compile native libraries (`.so`) and generate UniFFI Kotlin bindings:
```bash
./scripts/build-android.sh
```
This builds:
- `arm64-v8a` (Physical Android devices)
- `x86_64` (Android Emulator)
and places native libraries in `android/app/src/main/jniLibs/`.

### 3. Run the iOS App
Open the project in Xcode:
```bash
open ios/SSHApp.xcodeproj
```
Select your target device or simulator and press **Cmd + R**. For a connected iPhone, `make iphone` builds, installs and launches the app (`make help` lists the other targets; signing needs your unlocked login keychain).

### 4. Run the Android App
Open the `android/` project in Android Studio or build debug APK via Gradle:
```bash
cd android
./gradlew assembleDebug
```
The debug APK is generated at `android/app/build/outputs/apk/debug/app-debug.apk`.

### 5. Deploy the Zero-Knowledge Cloudflare Worker (Optional for Wake-ups)
```bash
cd scripts/apns-worker
cp wrangler.toml.example wrangler.toml
# Edit wrangler.toml with your Apple Developer Team ID & Key ID
npx wrangler secret put APPLE_P8_PRIVATE_KEY
npx wrangler deploy
```

### 6. Enable Agent Approval Hooks
Hooks are installed from the app: **Settings → Agents** (or the sessions menu → Agents) → a profile → **Review & install**. You see the exact entries first; the installer then merges the `ssh-app-hook` entries into the agent's own config (`<CLAUDE_CONFIG_DIR or ~/.claude>/settings.json` for Claude Code, `~/.gemini/config/hooks.json` for Google Antigravity, `~/.codex/hooks.json` for Codex, `~/.grok/hooks/ssh-app.json` for Grok), copies the script to `~/.ssh-app/bin/ssh-app-hook` and trusts this phone's key in `~/.ssh-app/allowed_signers`. Needs `python3` and OpenSSH (`ssh-keygen`) on the host. See [`docs/features/11-agent-hooks-and-launch-profiles.md`](docs/features/11-agent-hooks-and-launch-profiles.md) and [`docs/features/19-hooks-templates-and-host-guard.md`](docs/features/19-hooks-templates-and-host-guard.md).

### 7. Tests
```bash
cargo fmt --check && cargo clippy --all-targets -- -D warnings
cargo test -p ssh-core --lib --test hook_script    # unit tests and the real hook script
```
`crates/core/tests/loopback_sshd.rs` starts a throwaway `sshd` and a **private tmux server** on this machine; run it only as described in [`AGENTS.md`](AGENTS.md) (test isolation), never from inside a tmux session you care about without that isolation. Swift tests live in `ios/Tests/SSHAppTests` and need an iOS simulator.

## Security & Audits

Every milestone touching networking, cryptography, hooks or IPC goes through the **Hacker** adversarial audit gate.
All audit reports are in [`docs/security-findings/`](docs/security-findings/), one per area (core engine, tmux, approvals and the approval queue, port forwarding, AI assistant, snippets, host monitor, file browser, hooks and permissions, host guard). Known limits are written down in the reports, for example: a host-guard rule matches command text and is not a sandbox, and approvals are checked on the device only (no server).
