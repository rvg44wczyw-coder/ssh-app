# Review and adversarial pass: M19 (session permissions, terminal input), M20 (payments, off), M21 (hook templates, host guard)

Date: 2026-10-18. Mode: standalone, no live device. Live attacks only against local subprocesses and
a throwaway loopback sshd with a private tmux socket (`Sshd::tmux()`; tmux pid compared before and
after the runs: unchanged).

## 1. Scope
- M19: `permissions.rs` (`build_inspect_permissions_command`, parsing), `pane_context.rs`,
  `tmux.rs` (attach command, mouse), the wheel/tap path (Swift sends terminal bytes, no core code).
- M20: code only, switched off (`PAYMENTS` not set); checked that nothing enables it implicitly.
- M21: `hook_templates.rs`, `host_guard.rs`, `hook_safety.rs`, the host script; the earlier audit
  `2026-10-17-host-guard.md` and `2026-10-18-local-agents.md` already attacked the script, so this
  pass concentrated on what they did not touch.
Categories applied: input validation, subprocess/shell construction, file-system access driven by an
untrusted repository (the pane's folder), DoS. Ruled out: MITM/replay/downgrade/key confusion (no
new wire protocol or crypto), timing (no secret comparison), randomness (the only random value is the
marker tag of the inspect call, `rand::random`, unguessable per call).

## 2. Findings

### 1. [DoS] A FIFO planted as a project's settings file hangs the session-permissions read. Low
Location: `permissions.rs` `build_inspect_permissions_command`: `head -c ... "$p/.claude/settings.json"`
(and `settings.local.json`, and the profile file).
Scenario: the user opens an untrusted repository in a tab and taps *Permissions*. The repository
contains `.claude/settings.json` as a named pipe (`mkfifo`; git does not even need to track it, an
agent or a build script can create it). `head` blocks in `open(2)` waiting for a writer, the exec
channel never finishes, the sheet spins forever and a blocked `head` stays on the host.
Verified live: a plain `sh` run of the read hung past 4 s; the loopback test hung for 20 s
(`inspect hung`) and passed after the fix.
Fix (done): every read is guarded with `[ -f FILE ]`, so only regular files are read (symlinks to
regular files still work, FIFOs/devices/directories are skipped). Regression:
`session_permissions_report_reads_profile_and_project_rules_for_the_pane_folder` now plants a FIFO and
fails if the call takes more than 20 s (it fails without the fix, verified).

### 2. [Info] `tmux set -g history-limit 10000` changes the user's global tmux option
Location: `tmux.rs` attach command. Not a vulnerability; it changes a server-wide setting every time a
tab attaches (new panes only). Left as is; mouse mode is per session (`set -t`).

## 3. Checked and held
- Inspect command: the pane path is used only after a printable-characters check and always quoted
  inside double quotes; the markers carry a per-call random tag, so a project file cannot forge a
  section boundary; files are capped at 200 KB; nothing is ever written.
- The config dir detected from the Claude process environment must be an absolute existing directory
  and printable; used only as a quoted path.
- Host guard and templates: see `2026-10-17-host-guard.md` and `2026-10-18-local-agents.md`
  (command peeling, path normalisation, size cap, fail-closed OpenCode).
- Payments: `PAYMENTS` is not defined in the project build settings, the free-tier limits are
  inactive; the StoreKit code is not reachable from a shipped path.

## 4. Review notes (rev)
- Code matches the specs for M19 and M21; clippy `-D warnings` and the lib/hook/loopback suites pass.
- Not measured: line coverage (no coverage tool is set up in this repository). The M19/M21 logic has
  unit tests plus loopback/script tests; the Swift side (wheel, tap, schemes, icons, templates UI) is
  compile-tested only.
- Controversial: the inspect script is a long single-line shell string; a small embedded script run
  through `login_sh_script` (like the usage probe) would be easier to test and would also get the
  host-side watchdog. Not changed here (behaviour-preserving refactor with risk and no device check).

## 5. Verdict
Findings, highest severity **Low** (item 1, fixed). No Critical/High.
