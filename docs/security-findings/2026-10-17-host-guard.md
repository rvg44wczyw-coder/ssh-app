# Adversarial review: host guard and hook templates (2026-10-17)

## 1. Scope
`scripts/agent-hooks/ssh-app-hook.py` (guard rules, context, stop message, session registry), `crates/core/src/host_guard.rs`, `hook_templates.rs`, `hook_safety.rs`, `host_api.rs` (`read/apply_host_guard`, `list_agent_sessions`). Attacker: a prompt-injected agent that chooses tool input (command text, paths) and can run processes; an untrusted repository.
Live tests: the real script with a temporary `SSH_APP_HOME`, 40+ commands against `Bash(rm:*)`, path tricks against `Read(~/.ssh/**)`.

## 2. Findings
1. **Bypass of command-prefix rules, Medium (fixed in part).** First version matched the rule only against the raw segment. Passed: `/bin/rm x`, `env rm x`, `FOO=1 rm x`, `command rm x`, `"rm" x`, `r\m x`, `bash -c "rm x"`, `echo x | xargs rm`, `sudo -u root rm x`, `rm<TAB>x`, `RM x` (macOS volumes ignore case). *Fix:* each segment is also checked after peeling `sudo/env/command/nice/timeout/xargs…` (with option values), reducing the program to its lower-case base name, removing quotes and backslashes, looking into `sh -c "…"`, `$( … )` and backticks, and normalising whitespace. Re-run: all of the above are blocked, and `rmdir x`, `echo rm x`, `grep rm file` still pass. Regression test `host_guard_sees_through_the_cheap_ways_around_a_prefix_rule`.
2. **Residual, accepted (rule is not a sandbox).** Still passes: a command name built at run time (`$(echo rm) x`, `a=r; ${a}m x`), tools that delete without being named (`find . -delete`, `python3 -c "import os…"`), and writes through an editor-like program. *Mitigation:* the guard is one layer; deny the same things in the agent's own permissions, keep phone approval for `Bash`, and use the "Protect agent config" templates. The UI says rules are matched against the command text.
3. **Path rules.** `~`, `./`, `..` and symlinks are resolved before matching (`~/.ssh/../.ssh/id_x` and a symlink into `~/.ssh` are blocked). Not covered: hard links, bind mounts, case-insensitive spellings of the path.
4. **Guard file integrity, Low.** Read only if it is a regular file owned by the user, not a symlink, in a private (`0700`, owned) `~/.ssh-app`, at most 64 KB, at most 200 rules of 400 characters. The agent runs as the same user, so it *can* rewrite `guard.json` with a shell command (or an `Edit` unless denied) and remove its own restrictions. *Mitigation:* `Edit(~/.ssh-app/**)` is part of the `protect-agent-config` template, the `protect-agent-config-hook` template and the "Protect agent and hook settings" guard preset; a shell write cannot be seen by a hook. Same limit as any same-user control.
5. **Context injection, by design.** `additionalContext` and the stop message are text the user typed in the app; the script never copies prompt, command or file text into them (test: a hostile prompt is not echoed). Stop `block` is suppressed when `stop_hook_active` is set, so it cannot loop. Cost risk is stated in the app's warning.
6. **Allow rules, Medium if too broad.** An `allow` for `Bash` or `Edit` removes every prompt. The app warns on bare `Bash`, `Bash(*)`, `*`, `Edit`, `Write`; `deny` always wins and the allow list is only consulted when no deny/ask rule matched.
7. **Session registry, Low.** Files are written in a private folder, name = hash of agent+session id, at most 100 entries, entries older than 7 days dropped, fields length-capped and control-character stripped when listed. The tmux name is read with `tmux display-message` only when `$TMUX` is set (tests remove it).
8. **Templates.** Fixed command strings, no user text interpolated; guards read the event JSON with `json.load` and never `eval`. `snapshot-on-stop` uses `$(…)` on a fixed command and writes only `refs/ssh-app/snapshot`. `block-pipe-to-shell` contains a literal `|` in its regex (the lint flags it; the test whitelists that one).

## 3. Verdict
No finding blocks merge. Item 1 fixed; item 2 is inherent and documented; item 4 is the same-user limit already tracked in feature 15. Not covered: behaviour of the real Claude/Codex/Grok binaries (not run here).
