## Резюме для руководства (Executive Summary)

Комплект **Flextasks** представляет собой развитую систему автоматической оркестрации и маршрутизации задач между AI-моделями (Claude, Codex, Qwen, DeepSeek, Ollama) под управлением PowerShell 7 на платформе Windows. В системе реализован полезный функционал: учет квот моделей, автоматический сторож (`agents-watch`), запуск задач в изолированных Git worktree (`hardrun`) и попытки восстановления после сбоев.

Однако при детальном анализе логики и безопасности выявлены **критические уязвимости удаленного выполнения произвольного кода (RCE)**, архитектурные дефекты с **ложным прохождением тестов**, ненадежная файловая синхронизация с риском взаимоблокировок, а также уязвимости внедрения команд в SSH-транспорте.

## ЧАСТЬ 1. Разбор документа `COMPETITORS-2026-10-20.md`

### 1.1. Сильные стороны документа
1. **Точная фиксация версий**: Автор четко разграничивает редакции внешних инструментов (OMC v5.7.5, OmO v5.1.40, OpenHands v1.28.1, Cline v4.1.25), не смешивая CLI и веб-версии.
2. **Критический взгляд на маркетинг**: Справедливо подчеркнуто, что наличие деклараций «Team Mode» или «Autonomous Verify» в чужой документации не гарантирует реальной изоляции worktree или независимой верификации.
3. **Прагматичная позиция по миграции**: Обосновано, что переход на LangGraph или CrewAI потребует полной переписки локальных обвязок, поэтому первоочередной шаг — устранение дефектов текущего ядра.

### 1.2. Методологические и логические дефекты документа
1. **Иллюзия «детерминированного контракта»**:
   Документ противопоставляет Flextasks конкурентам за счет якобы «строгого контракта worktree и проверки». Однако код `hardrun.ps1` показывает, что контракт не детерминирован:
   - Если разметка `LOOPS.md` повреждена или заголовок изменен на `## Verify`, верификация молча отключается, и **непроверенный код признается успешным (`green`)**.
   - Потолок токенов (`TaskTokenCeiling`) проверяется **только post-factum между фазами**. Модель может израсходовать 100 000+ токенов за один запрос до того, как сработает лимит.
2. **Игнорирование проблемы распределенной идемпотентности**:
   В документе отмечено: *«watcher/TTL не доказывают exactly-once»*, но в дорожной карте P0–P2 отсутствует архитектурное решение. При сетевом сбое или таймауте агента fallback повторно вызывает другую модель, что приводит к **дублированию необратимых внешних операций и двойным списаниям**.
3. **Недооценка специфики Windows**:
   Вся ставка сделана на чистый PowerShell 7 на Windows. За скобками оставлены фундаментальные проблемы Windows: удержание блокировок файловыми дескрипторами Git (из-за чего удаление worktree падает с `AccessDenied`), неатомарность манипуляций с NTFS ReparsePoints и проблемы кодировок конвейера.

## ЧАСТЬ 2. Архитектурный ревью (`rev` gate)

### [DEFECT-01: HIGH] Ложно-положительный результат верификации при сбое парсинга
- **Локация**: `bin/hardrun.ps1`, строки 107–123, 831
- **Механика дефекта**:
  Если ключ `-Verify` не передан в CLI, вызывается функция `Get-LoopsVerify`. Она парсит `LOOPS.md` через регулярные выражения. Если заголовок написан как `## Verify` (с заглавной буквы) или нарушены границы code-block, функция возвращает пустую строку `""`.
  В строке 831 логика гласит:
  ```powershell
  if (-not $Verify) { return @{ ok = $true; tail = '' } }
  ```
- **Последствия**: Код без единого теста помечается как `green`, успешно мержится в интеграционную ветку и попадает в отчет как проверенный.
- **Требование `rev`**: Отсутствие валидной команды верификации при боевом запуске должно приводить к **немедленному аварийному останову (hard fail)**.

### [DEFECT-02: MEDIUM] Фатальная хрупкость вычисления корня проекта
- **Локация**: `bin/backlog-run.ps1`, строка 9
- **Механика дефекта**:
  ```powershell
  $projectRoot = Split-Path (Split-Path (Split-Path (Split-Path $Item -Parent) -Parent) -Parent) -Parent
  ```
  Корень вычисляется четырьмя жесткими вызовами `Split-Path`.
- **Последствия**: Если путь к файлу передан как относительный (`.\docs\backlog\running\task.md`) или файл лежит в подкаталоге другой глубины, переменная `$projectRoot` превращается в пустую строку или корень диска. Скрипт начинает выполнять сборку и git-операции в непредсказуемой директории операционной системы.
- **Требование `rev`**: Находить корень проекта динамически по наличию маркера `.git` или через `git rev-parse --show-toplevel`.

### [DEFECT-03: MEDIUM] Взаимоблокировки и падения журнала событий при нагрузке
- **Локация**: `bin/flextasks-state.ps1`, строки 46–54
- **Механика дефекта**:
  ```powershell
  while (-not $lock) {
      try { $lock = [IO.File]::Open((Join-Path $homeDir 'events.lock'), 'OpenOrCreate', 'ReadWrite', 'None') }
      catch [IO.IOException] { 
          if ((Get-Date) -ge $deadline) { throw 'Event journal is busy' }
          Start-Sleep -Milliseconds 25 
      }
  }
  ```
  Таймаут ожидания снятия блокировки составляет всего 5 секунд.
- **Последствия**: При параллельной работе нескольких задач и фонового сторожа на Windows файловый лок удерживается дольше 5 секунд. Скрипты падают с неперехваченным исключением `Event journal is busy`, прерывая выполнение пайплайна.
- **Требование `rev`**: Увеличить адаптивный таймаут до 30 секунд с экспоненциальным backoff или перейти на мьютексы операционной системы (`System.Threading.Mutex`).

## ЧАСТЬ 3. Аудит информационной безопасности (`hacker` gate)

### [VULN-01: CRITICAL] Удаленное выполнение произвольного кода (RCE) через Markdown-бэклог
- **Локация**: `bin/agents-watch.ps1`, строки 239–246
- **Описание уязвимости**:
  Сторож `agents-watch.ps1` автоматически считывает первую строку любого файла в `docs/backlog/*.md`:
  ```powershell
  $firstLine = Get-Content -LiteralPath $runningItem -Encoding UTF8 -TotalCount 1
  if ($firstLine -match '^verify:\s*(.+)$') { $verify = $Matches[1] }
  ```
  Полученная строка `$verify` без валидации передается в `backlog-run.ps1` $\rightarrow$ `hardrun.ps1` $\rightarrow$ запускается через PowerShell:
  ```powershell
  $check = '& { ... ' + $verifyBody + '; exit 0 }'
  Invoke-FlextasksProcess (Get-PowerShellExe) @('-NoProfile', '-Command', $check) ...
  ```
- **Сценарий атаки**:
  Злоумышленник через Pull Request, скомпрометированный subagent или стороннюю зависимость подкладывает в репозиторий файл `docs/backlog/feature.md` с первой строкой:
  `verify: powershell -enc <Base64_Payload_Reverse_Shell_Or_Credential_Dumper>`
  Фоновый сторож, запущенный на машине разработчика, подхватывает файл и **немедленно исполняет вредоносный код с правами текущего пользователя**.
- **Remediation**: Категорически запретить извлечение команд исполнения из текста задач. Команды проверки должны задаваться только администратором в доверенном защищенном конфигурационном файле (`agents.json`).

### [VULN-02: HIGH] Внедрение команд в SSH-транспорте (`Invoke-Ssh`)
- **Локация**: `bin/ask-agent.ps1`, строки 745–759
- **Описание уязвимости**:
  ```powershell
  $run = Invoke-FlextasksProcess 'ssh' ($sshOptions + @($cfg.host, "mkdir -p $($cfg.remoteInbox)")) $TimeoutSec
  ...
  $run = Invoke-FlextasksProcess 'ssh' ($sshOptions + @($cfg.host, (Expand $cfg.remoteCommand @{ remotePrompt = $rp; remoteOutput = $ro }))) $TimeoutSec
  ```
  Строки формируются через прямую строковую интерполяцию без экранирования спецсимволов шелла.
- **Сценарий атаки**:
  Если параметр `remoteInbox` или `remoteCommand` содержит символы `;`, `&&`, `$()`, кавычки или пайпы, на удаленном сервере выполняется произвольная команда.
- **Производительность**: Реализация выполняет **4 независимых сетевых подключения по SSH/SCP** на один единственный запрос (`mkdir` $\rightarrow$ `upload` $\rightarrow$ `exec` $\rightarrow$ `download`). При сетевой задержке 50 мс это создает паразитный оверхед в 1.5–3 секунды чисто на сетевые рукопожатия.
- **Remediation**: Использовать строгое экранирование параметров шелла (`quote_argument_for_shell`) и мультиплексирование сессий через SSH ControlMaster или обмен через stdin/stdout в одном процессе.

### [VULN-03: MEDIUM] Побег из песочницы окружения через `VerifyEnvKeep`
- **Локация**: `bin/hardrun.ps1`, строки 72 и 837–842
- **Описание уязвимости**:
  ```powershell
  $script:VerifyEnvKeep = @('PATH', 'SystemRoot', 'TEMP', 'TMP', 'USERPROFILE', 'HOME', 'JAVA_HOME', 'CARGO_HOME', 'RUSTUP_HOME', 'PATHEXT', 'ComSpec', 'windir', 'SystemDrive')
  ```
  Скрипт пытается скрыть боевые токены, очищая переменные окружения, но оставляет в доступе `PATH`, `CARGO_HOME`, `RUSTUP_HOME` и `USERPROFILE`.
- **Сценарий атаки**:
  Вредоносный агент в worktree создает локальный поддельный бинарник в папке сборки или прописывает алиас в `.cargo/config.toml`. При запуске команды верификации через унаследованный `$PATH` управление перехватывается поддельным исполняемым файлом, который считывает ключи из `$USERPROFILE/.ssh` или `$USERPROFILE/.aws`.
- **Remediation**: Использовать строго изолированный временный `TMP`/`TEMP` и детерминированный статический `PATH` без доступа к пользовательским директориям.

### [VULN-04: MEDIUM] Иллюзорная защита от утечки секретов через эвристический Regex
- **Локация**: `bin/ask-agent.ps1`, паттерн `SECRET_PATTERN_REGEX`
- **Описание уязвимости**:
  Фильтрация конфиденциальных данных основана на поиске регулярными выражениями ключевых слов (`API_KEY`, `TOKEN`, `BEARER`).
- **Сценарий обхода**:
  Любой агент или модель тривиально обходит этот фильтр:
  - Кодирование в Base64: `cat .env | base64`
  - Побайтовый вывод в Hex: `format-hex .env`
  - Разрыв токена пробелами или дефисами.
- **Remediation**: Защита на уровне файловой системы (запрет доступа к файлам `.env`, ключам и секретам через права доступа ОС и блокировку перечисления директорий), а не попытка парсить текст регулярками на выходе.

### [VULN-05: HIGH] Внедрение кода в аргумент `-Command` при вызове `Invoke-Verify`
- **Локация**: `bin/hardrun.ps1`, строки 850–853
- **Описание уязвимости**:
  ```powershell
  $verifyBody = "`$global:LASTEXITCODE = 0`n$Verify`nif (`$LASTEXITCODE) { exit `$LASTEXITCODE }"
  $check = '& { $ErrorActionPreference = "' + $verifyPref + '"; $PSNativeCommandUseErrorActionPreference = $true; try { ' + $verifyBody + '; exit 0 } catch { Write-Error $_ -ErrorAction Continue; exit 1 } }'
  Invoke-FlextasksProcess (Get-PowerShellExe) @('-NoProfile', '-Command', $check)
  ```
  Команда проверки склеивается как строковый литерал и передается в аргумент `-Command`.
- **Сценарий атаки**:
  Если переменная `$Verify` содержит сложные вложенные кавычки, обратные тики или символы подстановки переменных `$()`, происходит преждевременное закрытие строки и выполнение внедренного PowerShell-кода в контексте хоста.
- **Remediation**: Записывать тело верификации во временный изолированный файл скрипта `.ps1` и исполнять его через параметр `-File`, полностью исключив строковую интерполяцию в командной строке.

## ЧАСТЬ 5. Обязательный план устранения дефектов (Action Plan)

### Приоритет P0 (Критические исправления безопасности):
1. **Закрыть RCE в `agents-watch.ps1`**: Полностью удалить чтение строки `verify:` из файлов `.md`. Команда верификации должна жестко определяться вызывающей стороной или системным конфигом.
2. **Ликвидировать строковую конкатенацию в `Invoke-Verify`**: Передавать команду проверки через временный `.ps1` файл и параметр `-File`, прекратив использование динамического `-Command`.
3. **Безопасный SSH-транспорт в `ask-agent.ps1`**: Заменить множественные вызовы `ssh`/`scp` с неэкранированными путями на один вызов с передачей полезной нагрузки через `stdin`/`stdout`.

### Приоритет P1 (Архитектурная надежность):
1. **Детерминированный Fail при отсутствии Verify**: В `hardrun.ps1` сделать ошибку обязательной, если команда проверки не найдена (устранить дефект ложно-зеленых сборок).
2. **Динамический поиск корня проекта**: В `backlog-run.ps1` заменить цепочку `Split-Path x4` на надежное определение корня через Git API.
3. **Надежная синхронизация и блокировки**: Увеличить таймаут файловых блокировок в `flextasks-state.ps1` до 30 секунд с экспоненциальным шагом задержки.

### Приоритет P2 (Упреждающий контроль ресурсов):
1. **Упреждающий контроль токенов**: Замерять объем входного контекста до отправки в модель и обрывать сетевой стриминг при превышении лимита, не дожидаясь генерации сотен тысяч токенов.
2. **Идемпотентность повторных запусков**: Ввести уникальный UUID для каждого вызова с фиксацией состояния `in-flight`, чтобы предотвратить дублирование внешних эффектов при автоматическом fallback.
