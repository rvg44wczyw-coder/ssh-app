# 17. Terminal scroll/click, quick commands, local chat, session permissions, appearance

Status: implemented (Rust + iOS); on-device checks pending (scroll feel, alternate icons, config-dir detection).

## 1. Scroll and click through tmux
- tmux sends an attach client only the visible screen; history stays in tmux. The attach command sets `mouse on` for the session.
- A vertical pan becomes SGR mouse-wheel events (`ESC[<64;x;yM` up, `65` down), one step per text row, ×5 speed, CADisplayLink momentum. Wheel-up enters copy-mode, wheel-down at the bottom leaves it.
- A single tap sends SGR press+release (`ESC[<0;c;rM` / `m`) at the tapped cell, so "Jump to bottom" buttons in Claude/agy work. Dragging also dismisses the keyboard.
- Tests: loopback sshd (wheel scroll, tap click to a mouse-aware program) on a private tmux socket.

## 2. Keyboard accessory and quick commands
- The system bar already has Esc/Ctrl/Tab/arrows, so ours has: assistant, quick action, ^C, y/n, user commands, editor.
- User commands (`QuickCommand`, editor `QuickCommandsEditorView`); defaults: clear, /clear, /model, /help, /compact, /status.
- Confirmation: each command has `confirm` ("Ask before sending" switch in the editor). On tap the bar shows a confirmation dialog ("Run <label>?" / Cancel) and sends only after Run. On by default for `clear` and `/clear` (wipe the screen / the agent's context); other defaults are off. Saved commands without the field get the default from their text (custom `Codable` decoding), so no migration or reset is needed.

## 3. Local chat assistant
- Chat mode next to Command mode in the AI assistant sheet; host Ollama `/api/chat` over SSH.
- Caps: 60 messages / 96 KB; typed errors; Task cancellation drops the host command.
- Visibility setting: Auto / Always / Never (`ai_assistant_visibility`).

## 4. Session permissions
- Menu tile "Permissions": folder of the session, config folder (detected from the running Claude's `CLAUDE_CONFIG_DIR` via `ps eww`), start mode, user + project (shared/local) rules, suggestions from what is installed.
- Launch profile `permission_mode` → `--permission-mode` (Claude) / `--mode` (agy). Template `project-work`.
- Editor reads with `readAgentPermissionsChecked`: invalid rules (e.g. control characters) are shown escaped and removed only after confirmation.
- Antigravity's own command allowlist is internal and not writable.

## 5. Appearance (Settings → Appearance)
- Accent: 12 presets or a custom color (`#rrggbb` in `app_accent`); applied via `Color.appAccent` and root `.tint`.
- Terminal color schemes: 18 built-in + user schemes. Defaults per slot (general, Claude, Antigravity, Codex, Grok, shell), per-profile override. Resolution: profile → slot → general → built-in pick.
- Scheme editor: name, background, text, cursor, 16 ANSI colors, preview, "start from"; custom schemes in UserDefaults (`terminal_custom_schemes`, ids `custom-*`).
- Icons: per-profile symbol + color (tabs, profile list). The stored value is an SF Symbol name, `glyph:<text>` (the 9 terminal glyphs from the sheet in `docs/icons`: `>_ $ ~ # ▮ > [] — %`) or `img:<file>` (the user's own picture, chosen with the photo picker, cropped to a square, saved as 96 px PNG in Application Support/ProfileIcons, replaced pictures are deleted).
- Home-screen app icon = design + tint. Designs: classic, light, and the 5 from `docs/icons` (grid minimal / prompts / rounded / symbols / bold); tints: white + 7 accents (blue, teal, green, orange, red, pink, purple), picked in two rows in Settings. Alternate sets `AppIcon-<Tint>`, `AppIcon-Light`, `AppIcon-<Design>[-<Tint>]` (48 in all; the tinted grid copies are generated by `scripts/gen-tinted-icons.swift`, white→accent by luminance); previews `IconPreview-<Design>` are tinted live. iOS only accepts icons bundled with the app, so a user-uploaded picture cannot be a home-screen icon.

## 6. Model usage line on the main screen
- A thin line under the tabs (`SessionUsageStrip`): model, context fill bar and %, Claude tokens of the last 5 hours, and a red "Limit reached · resets HH:MM" when the transcript carries one. Tap refreshes. Hidden when no model runs in the tab's tmux session or the setting (Settings → Terminal → Model usage line) is off.
- Data: the existing read-only usage probe (`fetch_host_usage`, own SSH connection, up to ~15 s on the host); first read 3 s after a tab is shown, then every 90 s and on reconnect, only while the app is in the foreground and the tab is connected; never in the background (zero battery drain rule). Results younger than 60 s are reused.
- Not the plan's remaining quota (no safe source); numbers come from this host's transcripts.

## 7. Sessions home screen
- The app opens on a grid of session cards (`SessionsHomeView`): icon, title, server and tmux name, state dot, and a preview of the screen (last 7 non-empty lines, rendered through a headless SwiftTerm terminal from the tail of the tab's output, in the tab's color scheme; refreshed every 3 s while visible). Tap opens the terminal; long press opens the same session menu as the tabs (`SessionMenuItems`: Chat/Terminal, tmux sessions, Permissions, Agents, Rename, Close); the dashed card starts a new session (long press: agent profiles). Approval banners show on this screen too.
- In the terminal the top-left button returns to the list; touch and hold opens a jump menu: the other open sessions, the servers with their open sessions (and "New session here"), and "New session" (plain terminal, from an agent preset, or "With new settings…" which opens the agent profiles). A new session started from anywhere opens straight in the terminal.
- The tab strip stays (also with one session). The session actions (Chat/Terminal, tmux sessions, Permissions, Agents) are no longer a toolbar button: they sit at the top of the tab's long-press menu and of the settings dialog (second tap on the selected tab), above Rename and Close. They act on the pressed tab (it is selected first); the ones that need a connection are disabled while that tab is not connected. The toolbar keeps only the quick menu.
- Cards only show output for sessions that have been opened since the app started (the host session of the others is not attached in the background).

## 8. Folder for new terminals
- Settings → Terminal → New terminals: the folder on the host where **new plain terminals** start (default `~/Terminals`; empty = home). It is created with `mkdir -p` and passed to tmux as `new-session -d -c <dir>` (`SessionConfig.start_dir`, `build_tmux_attach_or_create_command`). A session that already exists keeps its own folder; agent tabs use their profile's working folder. Accepted values: `~`, `~/x` or an absolute path (400 characters, no control characters); the path goes through the same quoting as other host paths (test: shell text in the folder name stays text).
