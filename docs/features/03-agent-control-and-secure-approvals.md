## 1. Problem Statement & Scope

### 1.1. Context & Motivation
Remote autonomous coding agents (*Claude Code*, *Google Antigravity*, *OpenAI Codex*, *Cursor Agent*) run long-duration tasks inside background `tmux` sessions on the user's MacBook or remote development host. During execution, agents frequently block on critical safety gates:
1. **Tool / Shell Approvals (`PreToolUse` / `beforeShellExecution`)**: Asking user permission to run shell commands (`git push`, `rm`, database migrations).
2. **Clarification Questions**: Asking the user to pick an option or clarify architectural constraints.
3. **Task Completion / Failure Alerts**: Notifying the user when a multi-turn task concludes.

Competitors (such as *Moshi*) solve this by deploying a persistent proprietary Go daemon (`moshi-hook`) listening on local TCP ports and routing command text and session metadata through third-party cloud push gateways to Apple APNs. This violates the core privacy, battery, and zero-trust principles of our project:
- **No Plaintext HTTP on Host**: Opening listening HTTP ports exposes approval endpoints to local processes and network snooping.
- **Zero-Knowledge Privacy**: No command names, code snippets, or project paths may ever be sent to third-party cloud servers.
- **Zero Battery Drain**: The mobile app must not keep background polling sockets open while suspended.

### 1.2. Scope
- **In Scope**:
  1. **Host-Side Agent Hooks**: Lightweight hooks for *Claude Code* (`~/.claude/settings.json`) and *Google Antigravity* (`beforeShellExecution`), communicating via a private Unix Domain Socket (`0600`).
  2. **Zero Network Attack Surface**: No listening TCP/HTTP ports on the host. Mobile clients communicate with the approval manager strictly through authenticated SSH channels (`russh` with Ed25519).
  3. **Hardware-Signed Approvals**: Mobile approvals signed using the iPhone's hardware-backed Ed25519 private key in Secure Enclave / iOS Keychain. Host verifies the signature against `~/.ssh/authorized_keys` before unblocking the agent.
  4. **Zero-Knowledge APNs Wake-up**: A stateless Cloudflare Worker acting as an APNs trigger, forwarding *only* an opaque device token with an empty wake-up ping ($0 cost, 0 bytes of sensitive data).
  5. **iOS Notification Service Extension & ActivityKit**: Dynamic Island and lock-screen Live Activities with actionable `[Approve]` / `[Deny]` buttons.
  6. **Mobile Review & Workflow**: Dual-mode SwiftUI viewer (Raw Terminal $\leftrightarrow$ Structured Chat View), native Git Diff viewer, and accessory keyboard bar for agent control.
- **Out of Scope**:
  - Cloud synchronization of prompt history across devices.
  - Third-party webhook providers (Slack, Discord).

## 2. Domain Models & Cryptographic Protocols

### 2.1. Host & IPC Models (`crates/core`)

```rust
use serde::{Deserialize, Serialize};

/// Unique identifier for an agent approval request.
pub type ApprovalId = String;

/// The target coding agent demanding interaction.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub enum AgentType {
    ClaudeCode,
    GoogleAntigravity,
    Codex,
    Generic(String),
}

/// An approval request generated by an agent hook on the host.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct PendingApproval {
    pub id: ApprovalId,
    pub agent: AgentType,
    pub command: String,
    pub cwd: String,
    pub timestamp_sec: u64,
    pub nonce: String, // 32-char hex random nonce (CSPRNG)
    pub command_hash_sha256: String,
}

/// Signed decision returned by the mobile client.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct SignedApprovalDecision {
    pub id: ApprovalId,
    pub approved: bool,
    pub client_public_key_openssh: String,
    pub signature_hex: String, // Ed25519 signature over CanonicalSigningPayload
    pub timestamp_sec: u64,
}

/// Canonical payload format for cryptographic signing and verification.
/// Prevents malleability and replay attacks.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct CanonicalSigningPayload {
    pub id: ApprovalId,
    pub command_hash_sha256: String,
    pub nonce: String,
    pub timestamp_sec: u64,
    pub approved: bool,
}

impl CanonicalSigningPayload {
    pub fn to_bytes(&self) -> Vec<u8> {
        format!(
            "SSH_APP_APPROVAL_V1:{}:{}:{}:{}:{}",
            self.id, self.command_hash_sha256, self.nonce, self.timestamp_sec, self.approved
        )
        .into_bytes()
    }
}
```

### 2.2. UniFFI Interface Definition

```rust
#[uniffi::export]
pub fn create_canonical_signing_bytes(
    id: String,
    command_hash_sha256: String,
    nonce: String,
    timestamp_sec: u64,
    approved: bool,
) -> Vec<u8> {
    let payload = CanonicalSigningPayload {
        id,
        command_hash_sha256,
        nonce,
        timestamp_sec,
        approved,
    };
    payload.to_bytes()
}

#[uniffi::export]
pub fn verify_approval_signature(
    public_key_openssh: String,
    canonical_bytes: Vec<u8>,
    signature_hex: String,
) -> Result<bool, SshError>;

#[uniffi::export]
pub fn hash_command_sha256(command: String) -> String;
```

## 3. Host-Side Architecture: Unix Domain Socket & SSH Channel

### 3.1. Local IPC Socket
- Path: `$HOME/.ssh-app/run/control.sock`
- Permissions: Directory `0700` (`drwx------`), Socket file `0600` (`-rw-------`).
- Owned strictly by the logged-in user.
- **Protocol**: Single JSON-RPC style frame over Unix Domain Socket:
  - Agent Hook $\rightarrow$ Socket: `{"method": "request_approval", "agent": "claude", "command": "git push"}`
  - The local manager writes to the pending queue and notifies the Cloudflare wake-up gateway.
  - The agent hook blocks on read until a signed response is written back or a 120-second timeout occurs.

### 3.2. Mobile Client Access via SSH Subsystem / Exec
- The iPhone client connects to the Mac using standard `russh` authenticated with its Ed25519 key.
- It never touches an HTTP port. It executes:
  `ssh-app-ctl get-pending`
  and
  `ssh-app-ctl submit-decision '<signed_json>'`
- Communication is end-to-end encrypted by the SSH protocol (ChaCha20-Poly1305 / AES-256-GCM) across Tailscale.

## 4. Zero-Knowledge Wake-up Gateway (Cloudflare Worker)

### 4.1. Privacy Invariant
The Cloudflare Worker accepts only:
```json
{
  "device_token": "8a3f4b2c...",
  "notification_type": "alert" // or "liveactivity"
}
```
**Absolute Rule**: No command names, no project paths, and no agent details are sent to the Cloudflare Worker.

### 4.2. Worker Behavior
1. Validates that `device_token` matches hex format `^[a-fA-F0-9]{64}$`.
2. Signs an Apple APNs JWT token using the private `AuthKey.p8` stored in Cloudflare Encrypted Secrets (`ES256`).
3. Dispatches an HTTP/2 POST to `https://api.push.apple.com/3/device/<device_token>`.
4. Header: `apns-push-type: alert` (or `liveactivity`), `apns-priority: 10`.
5. Body: Silent/Wake-up JSON payload with `content-available: 1`.

## 5. iOS Lifecycle & ActivityKit Architecture

### 5.1. Wake-up Execution Flow
1. iPhone receives the APNs wake-up packet while locked in the user's pocket.
2. iOS wakes `NotificationServiceExtension` in the background (allocated ~20 seconds of runtime).
3. The Extension:
   a. Reads the host IP (Tailscale) and Ed25519 key from the shared App Group Keychain (`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`).
   b. Opens a quick SSH exec channel to the host via Rust Core: `ssh-app-ctl get-pending`.
   c. Receives the `PendingApproval` struct.
   d. Modifies the notification banner with:
      - Title: `Claude Code Approval Required`
      - Body: `Command: git push origin main`
      - Category: `AGENT_APPROVAL_CATEGORY` with action buttons `[Approve]` and `[Deny]`.
4. If a Live Activity is active, updates the ActivityKit state in Dynamic Island.

### 5.2. Action Execution & Cryptographic Signing
1. User taps `[Approve]` directly on the lock-screen banner or Apple Watch.
2. The iOS system handles the `UNNotificationAction`:
   a. Calls UniFFI `create_canonical_signing_bytes(...)`.
   b. Requests Ed25519 signature from Secure Enclave / Keychain.
   c. Connects to the host over SSH channel and calls `ssh-app-ctl submit-decision`.
   d. The host validates:
      - Nonce uniqueness (against in-memory bloom filter / SQLite table).
      - Timestamp freshness ($\Delta t \le 120 \text{ seconds}$).
      - Signature against `authorized_keys`.
   e. The host releases the agent hook with exit code `0`.

## 6. Mobile Review & UI Workflows (`ios/**`)

### 6.1. Dual-Mode Viewer: [Terminal] $\leftrightarrow$ [Chat View]
- **Terminal Mode**: Standard SwiftTerm PTY with TrueColor and dynamic resize.
- **Chat View Mode**:
  - Reads session transcript JSONL files (`~/.claude/` or `~/.gemini/antigravity-cli/brain/...`) via SSH SFTP/cat.
  - Renders native SwiftUI chat bubbles:
    - User prompts.
    - Agent responses with Markdown formatting.
    - Collapsible tool execution cards (`▶ Executed cargo test (Exit 0)`).

### 6.2. Native Git Diff Viewer
- Invokes `git diff` via SSH channel.
- Displays color-coded additions/deletions in SwiftUI.
- Allows one-tap revert (`git checkout -- <file>`) or full approval.

### 6.3. Accessory Keyboard Bar
- Specialized keyboard bar above the iOS keyboard:
  `[Approve (y)]`, `[Cancel (Ctrl+C)]`, `[Esc]`, `[Tab]`, `[tmux detach]`, `[Clear]`.

## 7. Security & Threat Modeling (Hacker Gate Criteria)

1. **Replay Attack Defense**: Every approval carries a 128-bit CSPRNG `nonce` and a timestamp. Nonces are recorded and rejected if seen again within a 10-minute window.
2. **Command Injection Prevention**: The command string is passed as pure serialized data within the JSON payload and canonical signing bytes. It is never interpolated into a shell string on the client or approval manager.
3. **Impersonation Prevention**: Decisions are cryptographically bound to the client's Ed25519 keypair. A malicious device on the Tailnet cannot approve commands on behalf of the authorized iPhone.
4. **Local Socket Isolation**: The Unix Domain Socket is protected by strict file permissions (`0600`) in a directory with `0700`.
