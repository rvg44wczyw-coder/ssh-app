# 35. Push relay (P3): "the agent needs you" with the app closed

- **Slug**: `push-relay`
- **Parents**: `16-host-service-analysis.md` §3 "Push path", §11 decisions 1–2; `26-host-agent.md` §2.4 (EventSink).
- **Status**: T1-T3 implemented (Worker deployed, host `push-*` commands and `PushSink`, core `host_push_*`, app card); T4 (device) pending. Needed the owner's Apple `.p8` key (have it), a Cloudflare account (logged in with wrangler), Key ID, Team ID.

## 1. Goal

When an agent on the Mac needs an approval, finishes, or waits for input while the app is closed
or the phone is locked, the phone shows a notification. The notification carries **no content**:
no command, path, project, agent name or message. Tapping it opens the app, which fetches the real
state over SSH exactly as today.

## 2. Parts

```text
agent (EventSink, only while a phone session lease exists)
  └─ curl (stdin config) ─HTTPS─► Worker (owner's Cloudflare) ─HTTP/2─► APNs ─► iPhone
phone app: asks permission, gets the device token, registers it over SSH (push-register)
```

1. **Worker** (`scripts/apns-worker`, replaces the draft). `POST /push` with JSON
   `{"token":"<64 hex>","category":"approval|finished|waiting|alert","env":"production|sandbox"}` and header
   `Authorization: Bearer <relay secret>`.
   - The secret is mandatory (the draft made it optional). Compared in constant time. Secret comes from a
     Worker secret (`RELAY_SECRET`), generated by `openssl rand -hex 32`, never committed.
   - Anything else is rejected: unknown category/env, token not 64 hex, body over 512 bytes, other
     methods, other paths. Unknown JSON fields are ignored but never forwarded.
   - Fixed payload per category (title `SSH App`, body one of four constant strings, `thread-id`
     per category, `interruption-level: time-sensitive` only for `approval`), `apns-push-type: alert`,
     `apns-priority: 10`, `apns-expiration` = now + 120 s for `approval` (the approval itself times out
     after 120 s) and 1 h for others, `apns-collapse-id` = category so repeated pushes replace each other.
   - Rate limit per token: 20 pushes per hour, in KV (`RATE` namespace; eventually consistent, good
     enough for abuse control). Over the limit: 429, nothing sent.
   - APNs host from `env`: `api.push.apple.com` or `api.sandbox.push.apple.com` (Xcode debug builds
     register sandbox tokens). The ES256 JWT is cached in the isolate for 50 minutes (Apple wants one
     per 20–60 minutes; a new one per request gets throttled).
   - APNs answers `410 Unregistered` / `400 BadDeviceToken`: the Worker returns 410 so the host can
     drop the registration.
   - No payload logging, no `console.log` of tokens; error bodies carry only a short reason code,
     never Apple's raw text or the key material.
2. **Host** (`crates/host`, macOS/Linux). New files under `~/.ssh-app/`:
   - `push.json` (0600, directory 0700): `{"token","env","url","secret","registered"}`. Written by
     `ssh-app-host push-register --stdin` (JSON on stdin so the secret never appears in argv);
     removed by `push-unregister`. `push-status` prints `{"registered":bool,"last":ts,"sent":n,"suppressed":n}`
     without the secret.
   - `PushSink: EventSink` maps `to` ∈ {approval, finished, waiting} to a category, drops everything
     else, and sends with `/usr/bin/curl` (Linux: `curl` from PATH) using `--config -` fed on stdin
     (URL, header with the secret, data), `--max-time 10`, `--fail`, `--proto =https`, no redirects.
     The helper stays free of a TLS stack. Runs on its own thread; a slow or failing relay never blocks
     the watcher. At most one push per category per 30 s per session (local limit, counted in
     `suppressed`). A 410 removes `push.json`.
   - Pushes are sent only while the agent lives, i.e. while a phone session lease exists (decision 1).
     So a push can arrive when the app was backgrounded within the lease; this is the accepted
     consequence of decision 1.
3. **App**.
   - Entitlement `aps-environment` (`development` for Debug, `production` for Release via build
     settings), capability Push Notifications, `UIBackgroundModes: remote-notification` not needed (alert pushes).
   - Asks for notification permission the first time the user turns on "Push" in Settings (not at launch).
   - `registerForRemoteNotifications`; the hex token is kept in the Keychain-less preferences (it is
     not a secret) and sent to every paired host through the same SSH exec channel as the other helper
     calls, whenever it changes and at connect time if the host's `push-status` says unregistered.
   - Settings: relay URL and relay secret (secret in the Keychain, `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`),
     a switch "Push when the app is closed", a test button ("Send test push" = `category: alert`).
     Both values can be pasted from a setup screen; no hidden defaults, so nobody else's relay is used by accident.
   - Notification categories: `approval` (tapping opens the Approvals sheet), others open the tab list.
     No actions on the notification itself in v1: approving from a lock screen would need a signed
     decision without seeing the command, which is exactly what the design avoids.

## 3. Security notes (for the hacker pass)

| Threat | Handling |
| --- | --- |
| Someone finds the Worker URL and spams the phone | Mandatory bearer secret, constant-time compare, per-token rate limit; the token is 64 random hex chars known only to the phone and its hosts |
| A compromised host/agent abuses the relay | It can only send one of four constant notifications to the one registered token, rate limited; no content channel exists |
| Secret leaks via process list | `push-register` reads JSON from stdin; curl is fed its config on stdin, so neither the token nor the secret is in argv |
| Secret leaks via logs/errors | Worker logs nothing; host errors say "relay failed (status)" only |
| Push content leaks to Apple/Cloudflare | Constant strings only; the Worker never sees command text because the host never has a field for it |
| SSRF / URL injection through `push.json` | `url` must be `https://` and end in `/push`, host chars checked; curl runs with `--proto =https`, no redirects |
| Token replay after the phone is replaced | 410 from APNs removes the registration; the app re-registers on the next connect |
| `.p8` exposure | Only as Worker secret (`wrangler secret put`), never in the repo, argv history or chat; the file stays outside the project |

## 5. Open items

- Notification Service Extension that fetches the real text over SSH: not in v1 (30 s limit, key access from an extension, and the privacy point of this design).
- Several relays or several phones per host: v1 registers one token per host.
- Release `aps-environment` needs the production App Store/TestFlight signing; Debug installs use the sandbox endpoint.
